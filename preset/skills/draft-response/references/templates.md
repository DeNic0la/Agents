# Response templates

Adapt each to the customer; never send one unchanged.

## Bug report acknowledgment

```
Hi [Name],

Thank you for reporting this. I can see how [specific impact] would be
frustrating for your team.

I've confirmed the issue and escalated it to our engineering team as
[priority level]. Here's what we know so far:
- [What's happening]
- [Cause, if known]
- [Workaround, if available]

I'll update you by [specific date and time] with a resolution timeline.
In the meantime, [workaround details, if applicable].

Let me know if this affects you in other ways I should know about.

Best,
[Your name]
```

## Billing or account issue

```
Hi [Name],

Thank you for reaching out. Billing issues need prompt attention, and I
want to make sure this is resolved quickly.

Here's what I see on your account:
- [What happened, factually]
- [Impact on the account: charges, access, ...]

Here's what I'm doing to fix it:
- [Action 1, with timeline]
- [Action 2, if applicable]

[If fixed now: "This has been corrected; you'll see the change within [timeframe]."]
[If it needs investigation: "I've escalated this to our billing team and
will update you by [specific date]."]

I'm sorry for the inconvenience. Let me know if you have questions
about your account.

Best,
[Your name]
```

## Feature request you won't build

```
Hi [Name],

Thank you for sharing this. I can see why [capability] would be valuable
for [their use case].

I discussed it with our product team, and it isn't something we plan to
build in the near term, mainly because [honest, respectful reason: a
narrow use case, a conflict with our architecture direction, ...].

I still want to make sure you can reach your goal. Some alternatives:
- [Alternative 1]
- [Alternative 2]
- [Integration or workaround, if applicable]

I've recorded your request in our feedback system, and I'll let you
know if our direction changes.

Would any of these work for your team? Happy to dig into any of them.

Best,
[Your name]
```

## Outage or incident

```
Hi [Name],

I wanted to let you know directly about an issue affecting
[service or feature], which I know your team relies on.

**What happened:** [Clear, non-technical explanation]
**Impact:** [How it affects them specifically]
**Status:** [Investigating / Identified / Monitoring / Resolved]
**Expected resolution:** [Specific time if known, or "we'll update every X hours"]

[If applicable: "In the meantime, you can [workaround]."]

I'm tracking this personally and will update you as soon as it's
resolved. You can also follow [status page URL] for live updates.

I'm sorry for the disruption. [What we're doing to prevent a recurrence,
if known.]

[Your name]
```

## Follow-up after silence

```
Hi [Name],

Checking in: I sent [what you sent] on [date] and wanted to make sure
it didn't get lost.

[Short reminder of what you need from them or what you're offering]

If now isn't a good time, just tell me when would be better and I'll
reconnect then.

Best,
[Your name]
```

## Internal escalation note

```
ESCALATION: [Customer name]: [One-line summary]

Urgency: [Critical / High / Medium]
Customer impact: [What's broken for them]
History: [2-3 sentences of background]
What I've tried: [Actions so far]
What I need: [Specific help or decision]
Deadline: [When it must be resolved]
```
