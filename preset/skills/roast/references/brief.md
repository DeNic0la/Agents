# The brief

Every seat receives exactly this brief and nothing else. Keep it factual: no opinions about whether the idea is good, and no hints about what you expect the verdict to be.

```markdown
# Brief: <idea in one line>

## The idea
<What would be built or changed, concretely. Name components, interfaces, data.>

## The problem it solves
<Who is hurting today and how, with evidence if any: incidents, metrics, issues, user complaints.>

## How it works today
<The current approach and the relevant code paths, with file paths.>

## Constraints
<Team size, deadline, runtime and platform, compatibility promises, budget, compliance.>

## Alternatives considered
<Including "do nothing". One line each.>

## What success looks like
<A measurable outcome and when it should be visible.>

## Open unknowns
<What nobody knows yet. Don't fill these in with guesses.>
```

If a section is empty because nobody knows, write "unknown". Don't leave it out. An unknown is something the panel should see.
